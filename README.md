# uhooks5

`uhooks5` is a per-process dark-theme shim for the classic Windows Task
Manager. It is injected at the PE entry point and themes Task Manager locally
(no global system colour/theme changes).

The project uses a freestanding MinHook-based blob, linked with LTO and no C
runtime, and appends it to a clean Task Manager binary as a `.dark` section.

## Layout

| path | purpose |
|---|---|
| `build.py` | builds the shim blob and injects it into the clean Task Manager binary |
| `inject.py` | appends the linked blob as `.dark`, patches the entry trampoline, and writes the output EXE |
| `derive_offsets.py` | derives the PE-specific addresses used by `inject.py` |
| `fetch_tm_7z.py` | extracts `taskmgr.exe` and its MUI from the WinRE image via `7z.dll` |
| `merge_mui.py` | merges MUI resources into a Task Manager EXE |
| `patch_dpi.py` | removes DPI awareness from a Task Manager EXE |
| `capture_win.py` | captures a Task Manager window/tab with `PrintWindow` |
| `src/` | shim source (C/C++/assembly and `common.h`) |
| `minhook-master/` | stock MinHook source |
| `captures/` | verification screenshots |
| `uhooks5.exe` | built artifact |

`bin/` is generated by the build and contains intermediate objects and
`stub.bin`; it is not required in a source checkout.

`listgrid.c` and `combodark.c` may be present under `src/` but are not part of
the current build.

## Build requirements

- Windows x64.
- A merged-MUI Task Manager EXE intended to be taken from the `target/` folder,
  with the expected SHA-256:
  `ac757163d73491ea8cf6b94088eb34beccad9ee9f0ff47b297897b162e153cab`.
  Set `UH_TARGET` to the merged EXE path.
- Python 3 with `pefile` installed.
- MinGW-w64 toolchain with `gcc`, `g++`, `ld`, and `objcopy` on disk.
  The default toolchain directory is `~/Downloads/MinGW/bin`.
- The stock `minhook-master/` tree must be present.

Environment overrides:

| variable | effect |
|---|---|
| `UH_TARGET` | path to the merged-MUI base EXE |
| `UH_BASE_SHA256` | expected base EXE hash |
| `UH_MINGW` | path to the MinGW `bin` directory |

Build:

```powershell
python build.py uhooks5.exe -DELEMS_LISTGRID=0
```

`-DELEMS_LISTGRID=0` is retained for compatibility but has no effect in the
current build; `listgrid` is not in the module list. The build creates `bin/`
and `src/` if they do not exist and writes `uhooks5.exe`.

## Fetching taskmgr from WinRE

`fetch_tm_7z.py` locates the Windows Recovery partition, opens its `WinRE.wim`
without assigning a drive letter, and extracts:

- `target\taskmgr.exe`
- `target\taskmgr.exe.mui`

It loads `7z.dll` directly and supplies the WIM as a Python `IInStream`. This
avoids 7-Zip's command-line path preprocessing, which calls `FindFirstFile` and
fails on the protected recovery directory. In the tested configuration it runs
without elevation.

Requirements:

- Windows x64 and 64-bit Python;
- `7z.dll` from an installed 7-Zip, or `--7z-dll` / `SEVENZIP_DLL` / `7Z_DLL`.

Usage:

```powershell
python fetch_tm_7z.py
python fetch_tm_7z.py --target path\to\target
python fetch_tm_7z.py --wim path\to\WinRE.wim
```

`--target` defaults to `target` next to the script. `--wim` overrides recovery
partition discovery. The tool prints the selected recovery partition, WIM,
`7z.dll`, and SHA-256 hashes of both extracted files.

## Deriving inject.py offsets

`derive_offsets.py` derives the PE-specific addresses used by `inject.py`
instead of requiring them to be edited by hand:

- `STUB_VA` - next section-aligned VA after the image;
- IAT slot VAs for `LoadLibraryW`, `GetProcAddress`, `GetModuleHandleW`, and
  `GetCurrentProcessId`;
- `ORIG_CTOR` / `ORIG_RET` - the displaced entry-trampoline targets.

```powershell
python derive_offsets.py
python derive_offsets.py path\to\taskmgr.exe
python derive_offsets.py --json
```

The target defaults to `UH_TARGET` / `DARK_SRC`, then
`../../taskmgr-dark-neo.exe`. The output is ready to copy into `inject.py`:

```python
STUB_VA = 0x140069000
IAT_LoadLibraryW = 0x140024c80
IAT_GetProcAddress = 0x140024c38
IAT_GetModuleHandleW = 0x140024c58
IAT_GetCurrentProcessId = 0x140024d50
ORIG_CTOR = 0x140001984
ORIG_RET = 0x1400011c0
```

## Merging MUI resources

`merge_mui.py` merges menu, dialog, string, accelerator, and message-table
resources from an MUI file into a Task Manager EXE. It appends the merged
resource blob as a new `.rsrc2` section and rewrites the resource data
directory.

Requirements:

- Windows x64;
- Python 3 with `pefile`;
- a source EXE and matching MUI file.

Usage:

```powershell
python merge_mui.py <source.exe> <source.mui> <output.exe>
```

Example:

```powershell
python merge_mui.py taskmgr-winre.exe en-US\taskmgr-winre.exe.mui merged\taskmgr-winre.exe
```

The script prints the merged resource counts, `.rsrc2` layout, output path, and
PE checksum. Merging `taskmgr-winre.exe` with
`en-US\taskmgr-winre.exe.mui` reproduces the clean
`taskmgr-dark-neo.exe` SHA-256:

```text
AC757163D73491EA8CF6B94088EB34BECCAD9EE9F0FF47B297897B162E153CAB
```

## Applying the DPI-unaware patch

`patch_dpi.py` converts a Task Manager PE to a DPI-unaware executable. It
changes both places that can establish DPI awareness:

- every direct `call [rip+slot]` to `SetProcessDPIAware` in `.text` is replaced
  with six NOP bytes;
- every `<dpiAware>true</dpiAware>` element is removed from `RT_MANIFEST`
  resources, including resources in an appended `.rsrc2` section.

The manifest entry's resource size is updated and the leftover bytes are
zero-filled. The PE checksum is then recomputed. Running the script again on an
already patched file makes no code or manifest changes.

Requirements:

- Python 3 with `pefile`.

Usage:

```powershell
python patch_dpi.py <input.exe>
python patch_dpi.py <input.exe> --output <output.exe>
```

If `--output` is omitted, the result is written next to the input with a
`-dpifix` suffix, for example `taskmgr.exe` → `taskmgr-dpifix.exe`.

The script prints the source and destination paths, each patched call VA, each
manifest path with its old and new size, and the new checksum.

## capture_win requirements and use

Requirements:

- Windows interactive desktop/session with the Task Manager window visible.
- Python 3 with:
  - `Pillow` for PNG output;
  - `uiautomation` for tab verification and tab switching.
- Permission to query and foreground the target Task Manager process.

The tool uses `PrintWindow(PW_RENDERFULLCONTENT)`, so the target window does
not need to be free of overlapping windows. Tab switching is content-verified
through UIA.

Basic use:

```powershell
python capture_win.py --process uhooks5 --tab Performance --output captures/performance.png
```

Selectors (exactly one is required):

- `--process <name>` - process name;
- `--pid <pid>` - process id;
- `--title <text>` - visible window title substring.

Options:

- `--tab <name|index>` - switch to a Task Manager tab before capture, e.g.
  `Applications`, `Processes`, `Performance`, `Networking`, `Users`,
  `Services`;
- `--output <path>` - required output PNG path;
- `--delay <seconds>` - settle delay before capture (default `0.3`; values above `1.0` are clamped to `0.3`);
- `--menu-accel <char>` - open a menu by accelerator before capture;
- `--popups-prefix <prefix>` - also capture popup windows such as menus.

Example with a process name and tab:

```powershell
python capture_win.py --process uhooks5 --tab Applications --output captures/applications.png
```

The tool prints the selected HWND/class, the visible page after tab switching,
and the final image size/path.
